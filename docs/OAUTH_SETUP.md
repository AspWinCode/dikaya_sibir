# Вход через Яндекс ID и VK ID: где взять ключи и как подключить

Кнопки «Яндекс ID» и «VK ID» на экране входа работают, только если на сервере заданы ключи приложений.
Сейчас их нет, поэтому кнопки ведут на страницу ошибки.

Нужно получить у каждого сервиса **ID приложения** и **секрет**, указать там адрес возврата
(**Redirect/Callback URI**) и вписать значения в `infra/.env` на сервере.

> Секреты (`CLIENT_SECRET`) не отправляйте в чаты и не коммитьте в репозиторий. Вписывайте их только в `.env` на сервере.

## Адреса возврата для нашей платформы

| Сервис | Redirect / Callback URI |
|---|---|
| Яндекс ID | `https://platform.lesovik.site/auth/yandex/callback` |
| VK | `https://platform.lesovik.site/auth/vk/callback` |

Адрес должен совпадать **символ в символ** (https, без лишнего `/` в конце).
Базовый домен для VK: `platform.lesovik.site`.

---

## 1. Яндекс ID

1. Откройте <https://oauth.yandex.ru/> и войдите **аккаунтом организации** (не личным, чтобы приложение не пропало вместе с сотрудником).
2. Нажмите **«Создать приложение»** (или «Зарегистрировать новое приложение»).
3. Заполните:
   - **Название:** «Лесовик» (его увидят пользователи на странице согласия).
   - **Иконка:** логотип платформы (по желанию).
   - **Платформы:** отметьте **«Веб-сервисы»**.
   - **Callback URI #1:** `https://platform.lesovik.site/auth/yandex/callback`
   - **Доступы (права):** добавьте **«Доступ к адресу электронной почты» (`login:email`)** и **«Доступ к логину, имени и фамилии, полу» (`login:info`)**.
     Платформа берёт почту пользователя, без `login:email` вход не сработает.
   - **Почта для связи** — рабочая (например, `info@lesovik.site`).
4. Нажмите **«Создать приложение»**.
5. На странице приложения скопируйте:
   - **ID** → это `YANDEX_CLIENT_ID`;
   - **Пароль** (Client secret) → это `YANDEX_CLIENT_SECRET`.

Модерация для входа через Яндекс обычно не нужна: приложение работает сразу, а пользователь видит стандартное окно согласия.

---

## 2. VK

1. Откройте кабинет разработчика VK: <https://id.vk.com/about/business/go> (VK ID для бизнеса) и войдите аккаунтом, с которого будет управляться приложение. Нужна подтверждённая страница.
2. Создайте приложение (платформа **«Веб»**/«Сайт»):
   - **Название:** «Лесовик».
   - **Базовый домен:** `platform.lesovik.site`.
   - **Доверенный Redirect URL:** `https://platform.lesovik.site/auth/vk/callback`
   - **Права (scope):** почта пользователя (`email`).
3. В настройках приложения скопируйте:
   - **ID приложения** → `VK_CLIENT_ID`;
   - **Защищённый ключ** (Client secret) → `VK_CLIENT_SECRET`.
4. Для публикации приложению обычно нужно заполнить **ссылки на «Политику конфиденциальности» и «Пользовательское соглашение»**
   и пройти проверку. Это связано с пунктом 13 списка замечаний (юридические документы): пока страниц нет, VK может не пропустить приложение.

> **Важно про VK.** Платформа сейчас использует классическую схему VK OAuth
> (`oauth.vk.com/authorize`, `oauth.vk.com/access_token`, `users.get`, версия API 5.199).
> VK постепенно переводит новые приложения на **VK ID** с другой схемой (`id.vk.com`, PKCE).
> Если в кабинете создаётся приложение нового типа и вход выдаёт ошибку вроде `invalid_request` или «неверный redirect_uri»
> при совпадающих адресах, значит, нужно переписать вход под VK ID (небольшая задача на бэкенде и фронтенде).
> Скажите, и я это сделаю.

## 3. Записать ключи на сервер

На сервере откройте файл и добавьте (или поправьте) строки:

```bash
nano /opt/lesovik/repo/infra/.env
```

```env
YANDEX_CLIENT_ID=<ID приложения Яндекса>
YANDEX_CLIENT_SECRET=<пароль приложения Яндекса>
YANDEX_REDIRECT_URI=https://platform.lesovik.site/auth/yandex/callback

VK_CLIENT_ID=<ID приложения VK>
VK_CLIENT_SECRET=<защищённый ключ VK>
VK_REDIRECT_URI=https://platform.lesovik.site/auth/vk/callback

# Базовый адрес платформы (используется в ссылках из писем: сброс пароля, приглашения)
FRONTEND_URL=https://platform.lesovik.site
```

Затем перезапустите бэкенд, чтобы он прочитал новые значения:

```bash
cd /opt/lesovik/repo && docker compose -f infra/docker-compose.server.yml --env-file infra/.env up -d backend
```

Без `*_REDIRECT_URI` бэкенд подставит значение по умолчанию `http://localhost:5173/...`, которое на сервере не работает
(именно из-за этого сейчас кнопки ведут не туда).

## 4. Как проверить

1. В браузере (лучше в окне инкогнито) откройте `https://platform.lesovik.site/signin`.
2. Нажмите **«Яндекс ID»**: должно открыться окно Яндекса с названием «Лесовик», а после согласия вернуть вас в платформу уже авторизованным.
3. То же для **«VK ID»**.
4. Новый пользователь создаётся автоматически по почте из аккаунта. Если у VK-пользователя скрыта почта, платформа создаст
   технический адрес вида `vk_<id>@vk.com`.

Быстрая диагностика без входа: ссылка `https://platform.lesovik.site/api/v1/auth/yandex` (и `.../vk`) должна перенаправлять
на страницу сервиса с **непустым `client_id`** и `redirect_uri=https://platform.lesovik.site/...`.
Пустой `client_id` или `localhost` в адресе означает, что ключи ещё не подхвачены.

## 5. Частые ошибки

| Симптом | Причина |
|---|---|
| «redirect_uri mismatch» / «неверный redirect_uri» | Адрес в кабинете и в `.env` отличается хотя бы символом (http/https, `/` на конце) |
| Страница сервиса с ошибкой «invalid client» | В `.env` пустой или неверный `CLIENT_ID`; бэкенд не перезапущен |
| После согласия «Не удалось войти через внешний сервис» | Неверный `CLIENT_SECRET` или у Яндекса не выдан доступ `login:email` |
| VK не пропускает приложение | Нет ссылок на политику конфиденциальности и соглашение (пункт 13) |

Пока ключей нет, кнопки лучше скрыть, чтобы пользователи не попадали на страницы с ошибками. Это можно сделать отдельной правкой.
